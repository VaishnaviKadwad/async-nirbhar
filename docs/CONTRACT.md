# NIRBHAR API Contract

## Evidence and Incident

```text
Evidence {
  id: string
  kind: "report" | "sensor"
  category: string
  source_type: "student" | "guard" | "warden" | "smoke_sensor" | "temperature_sensor"
  zone_id: string
  occurred_at: string       # ISO 8601 timestamp
  state: "positive" | "normal" | "unavailable" | "contradictory"
  text: string, optional    # reports; omitted for sensor readings
  value: float, optional    # descriptive sensor reading
  unit: string, optional
  synthetic: boolean        # true for seed/demo data
}

Incident {
  id: string
  zone_id: string
  evidence: [Evidence]
  correlation_reason: string
  status: "normal" | "attention" | "high_priority" | "critical_review"
  response: string
  escalate_if: string
  deescalate_if: string
  unavailable_sources: [string]  # sorted source_types for evidence in state "unavailable"; defaults to []
}
```

Only evidence whose `state` is `"positive"` contributes to rule-engine hazard signals. Sensor `value` and `unit` are descriptive; there is no numeric threshold. Evidence with state `"normal"` still participates in correlation and creates an incident whose status is `"normal"` when no positive rule matches. Unavailable evidence also creates an incident, with status `"normal"` if no positive rule matches; its source type appears in sorted `unavailable_sources`. Consumers must display `unavailable_sources` and must not present a plain “Normal” state when unavailable sources are present.

## Correlation and IDs

Evidence is grouped by `zone_id` within 15 minutes of the group's earliest evidence. Report-to-report similarity uses the Dice coefficient over unique case-folded words; it measures lexical overlap, not semantic similarity. Correlation therefore depends on zone, time, and shared words in report text.

Incident IDs are UUID5 hashes of `zone_id` plus the sorted evidence IDs. The ID is stable while that exact evidence set is unchanged. Adding evidence changes the incident ID; a decision submitted against the old ID returns 404 because the old incident no longer resolves. A zone with no evidence has no incident and is treated as `normal` by the zone-status consumer. One positive mild report creates an incident with status `attention`. Classroom 3 (Room C) must have no evidence to remain `normal`.

## Endpoints

### `POST /evidence`

Accepts an Evidence object. The server generates an ID when omitted.

- `201`: evidence stored and returned as an Evidence object.
- `409`: duplicate evidence ID.
- `422`: invalid Evidence fields or values.

### `GET /incidents`

Returns the current incidents as an array. Each item contains the Incident fields and `sop_citation`.

### `GET /incidents/{id}`

Returns the current incident matching the ID, or `404` with `Incident '<id>' not found`.

### `GET /incidents/{id}/explanation`

Returns exactly:

```json
{
  "summary": "string",
  "citation": "string",
  "uncertainty": "low | medium | high",
  "escalate_if": "string",
  "deescalate_if": "string"
}
```

The local model call takes about 8–14 seconds when warm. If the model is disabled or unavailable, the endpoint returns a deterministic template fallback. Unknown incident IDs return 404.

### `POST /incidents/{id}/decision`

Request body:

```json
{
  "action": "approve | modify | reject",
  "reason": "string, optional",
  "officer_id": "string"
}
```

- `200`: decision recorded in the persistent audit log. `modify` and `reject` require a non-empty reason. No external response or dispatch ticket is created; officers remain responsible for carrying out real-world procedures.
- `404`: incident ID does not resolve.
- `409`: the incident already has a recorded approval or modification decision.
- `422`: `modify` or `reject` has a missing or blank reason.

### `GET /audit`

Returns the append-only audit events in chronological insertion order.

## SOP Citation

Current API responses expose `sop_citation` as the string `"Review Required"`.

Agreed target shape: retain `sop_citation` as a string and add a separate `sop` object with `{title, text, score}`. Use `"Review Required"` for `sop_citation` whenever retrieval is not valid.
